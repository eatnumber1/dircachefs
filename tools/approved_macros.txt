# Macros dcfs may define (docs/style.md 1.2, rule-macros-discouraged).
#
# Macros are discouraged. A new one is justified only by a significant
# improvement, needs russ's approval, and he settles its name: DCFS_ by
# default, or a name he chooses. A new macro needs russ's approval: report it
# instead of adding it to this file. This file changes only by russ's
# ruling, or the orchestrator's for an internal helper of an approved macro;
# a third_party line names its library and needs no grant.
#
# russ, 2026-10-19: "maybe I spoke too strongly. I'm not looking to fully ban
# all propositions of a macro. Sometimes it's a significant improvement to
# have one (for example, ASSIGN_OR_RETURN and RETURN_IF_ERROR are significant
# readability improvements). But they're discouraged." and "if I'm granting an
# exception I'll likely want to exercise control over the name it's given, so
# may choose to exempt the prefix rule too."
#
# From this file `bazel run //tools:approved_macros -- --write` writes
# .clang-tidy's cppcoreguidelines-macro-usage.AllowedRegexp (the names with an
# allowance)
# and readability-identifier-naming.MacroDefinitionIgnoredRegexp (the names
# not marked prefixed); //tools:approved_macros_test fails when they disagree,
# when a C++ source defines a macro that is neither a header guard nor listed
# here, and when a name here is defined nowhere. The check only reads C++; the
# macros of the .c files are not listed.
#
# FORMAT: name|kind|date|allowance|grant
#   name       an identifier
#   kind       `prefixed` (the name starts with DCFS_), `exempt` (exempt from
#              the prefix and case rule: a Google-internal mirror, or a
#              private helper that ends in an underscore) or `third_party`
#              (the name is owned by a library, which the grant names)
#   date       of the grant
#   allowance  empty, or why no other language feature can express the macro
#              (russ, 2026-10-19: cppcoreguidelines-macro-usage "likely
#              should go un-exempted, as it's calling out macros that can be
#              implemented using other language features instead"); only
#              names with an allowance are in AllowedRegexp. A grant does not
#              imply one, and a name the check never reports needs none.
#   grant      russ's words, who approved it (an internal helper of an
#              approved macro may be approved by the orchestrator), or
#              `existing, pending 25.63 review`; for third_party, the library
# Header guards need no entry: they are exempt in general. Macros defined in
# third-party headers are never reported (clang-tidy's header filter).
# Lines marked "candidate" look like ones to remove: russ decides.
