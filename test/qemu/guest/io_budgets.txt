# I/O budgets (step 26.17): the most I/O a test may cause, as counts. Format:
# OP KIND MAX, OP a Bazel label, compared by guest/strace_lib.sh's
# strace_budget_compare against the COST line the guest prints (guest/init,
# guest/cost_lib.sh) with no tolerance: a count above its budget fails, naming
# both numbers. The one exception, interim (step 26.17c, russ 2026-10-18): the
# disk-request counts reads, writes, sectors_read, sectors_written, dcfs_reads
# and dcfs_writes (they move with the host's load) may exceed their budget by 2%
# rounded up, at least 1 (COST_DISK_COUNT_HEADROOM_PCT in strace_lib.sh); flushes
# and the byte counts stay exact. A deterministic count will replace it. Pinned
# numbers are not raised for it. KIND is one of
#
#   reads writes sectors_read sectors_written flushes
#       the disks of the test (the virtio disks, or the loop devices that are the
#       RAM disks), summed, from /sys/block/<disk>/stat: reads and writes
#       issued (completed plus merged into another request: the block layer
#       merges by the timing of its queue, so the completed count moves while
#       the issued one does not; README, "Budgets in three parts"), 512-byte
#       sectors, and flush requests (FLUSH/FUA: what an fsync costs the
#       device), between the start of the test and a sync after its end.
#       Everything on them counts: the test script's own file writes as much as
#       dcfs's.
#   dcfs_reads dcfs_writes dcfs_read_bytes dcfs_write_bytes
#       what the processes that run dcfs's code (the daemon, or a unit test's
#       binary) caused on those disks, from the io controller's io.stat of their
#       cgroup. This is /proc/<pid>/io's read_bytes and write_bytes for a daemon
#       that may have been started and killed several times, which /proc/<pid>/io
#       (gone with the process) cannot give; its syscr and syscw are not counted
#       (strace_op's counts of the daemon's syscalls are the budgets for those).
#
# A count that is below its budget passes, so a count that is not measured
# passes everything: run-qemu.sh fails a target with a budget for reads of more
# than 0 whose guest counted no read, and guest/cost_lib.sh's cost_selfcheck
# (boot_test, ram_disks_test) fails if a write of 1 MiB does not show.
#
# Pinned per kernel, like the strace goldens (guest/syscall_traces.sh): these
# are the counts of the pinned Alpine linux-virt, 6.18 of branch v3.24, on ext4,
# with the quiet kernel (guest/init). A bump of the kernel may re-baseline them
# in its own commit, with before and after; nothing else may: a count that rises
# for any other reason is a finding. Not held for a sanitizer, coverage, TCG or
# noisy-kernel run (strace_lib.sh, budget_unheld_reason).
#
# Each budget is the highest count seen plus the spread seen, over the runs
# measured for it: a count that never varied is exact, one that moves (the
# flushes and the daemon's writes of a test that writes, the cache database's
# requests) has the slack the runs showed. The comment at the end of a line is
# the range seen. Each section says how many runs measured its lines: the
# counts other than reads and writes are those of step 26.17 (8 quiet runs, 4
# beside five other guests, 3 beside 8 busy loops), and reads and writes were
# measured again in step 26.34, when they came to mean requests issued. A target
# with no line is reported, not held. test/qemu/README.md, "Budgets in three
# parts", has the table of what varied.
#
# //test/qemu:xfstests_1_test_ext4 has only read-side lines (step 26.37): its
# shard runs generic/364, which loops direct writes and fsyncs for 10 s, so what
# it issues is a rate of the host. The shard's writes were 13,644 to 13,965 at
# a load average of 36 (3 runs, 85% host CPU pressure, 853 to 1,060 of them
# generic/364's) and 57,097 on CI's quiet runner (45,012 of them), with the
# same code; flushes 1,787 to 1,971 and 15,620; the daemon's writes 2,392 to
# 2,514 and 14,896; the sectors written 4.46 to 4.55 million. No line for a
# count that moves with the host's speed can hold on both, so writes,
# sectors_written, flushes, dcfs_writes and dcfs_write_bytes have none; the
# reads do not move (below).
